## 動的アクセス制御の最適解を探して 〜 IaC の自動生成と OPA で実現するスケーラブルな権限管理基盤〜
### 勉強になったこと

データ基盤の権限管理って、課題がとにかく多い
データセットやテーブル単位で細かく権限を分けたい（共有リソースは Read Only、でも自分のリソースではオーナーとして振る舞いたい）
カラム単位でもアクセスを絞りたい（センシティブなデータとか）

IAMは、一般的にRBACで管理することが多いけど、「同じロールでも、担当業務ごとに見られるデータは最小限にしたい」となると、ABAC的な要件になってくる
:::message
たとえば、A さんと D さんのロールはどちらも「アナリスト」。でも A さんは B 業務、D さんは C 業務の担当なので、A さんには C 業務のデータは見せたくない、みたいなイメージ
:::

じゃあ、障壁はあるけど、RBAC から ABAC的にしていかないといけないよね。
障壁①：IAMは加算ができない
障壁②：Roleが増えちゃう

障壁を乗り越えるためにこんなプレ運用をしている：
①Terraform の構成自体は静的に保つ
②**権限ロジックは Go に任せて、Go で Terraform のコードを生成する（Addon や Exclude もここで面倒を見る）**
③それと並行して、OPA の Rego で Terraform の Plan を CI でチェックする

### 感想
業務では、ABAC で権限管理をしていてIaC化もしていないから早くなんとかしたい。。
プライベートではIAMもTerraformで管理しているが、高級言語で自動生成する仕組みで試してみるのもありかも？

## 実測データからサービスの成長余力を測る。負荷シナリオ・テストデータ・限界値の設計
