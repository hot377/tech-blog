## はじめに

2026年8月19日、1ロールあたりの管理ポリシーのデフォルトクォータが10個から20個に引き上げられたと発表されました。

業務ではカスタマー管理ポリシーを使用しているのですが、それはAWS管理ポリシーの上限が低かったからなのかもしれないと今更ながらに思いました。

https://aws.amazon.com/jp/about-aws/whats-new/2026/08/aws-iam-quota-increase/

本記事では、クォータ値とアタッチできるポリシーの個数について確認します。
なお、ロールの作成とポリシーのアタッチについては、Terraformを使用してデプロイします。

## この記事で学べること

- IAMロールの管理ポリシー上限がデフォルト20個になったことと、これがロール限定の変更である点
- 上限に達したときに実際に返るエラーメッセージ

## 想定読者

- 管理ポリシーの上限10個に合わせてポリシーを統合していた人
- IAMのアップデート情報を知りたい方
- デフォルトクォータについて知りたい方

:::note
前提知識として、IAMのロール・管理ポリシー・インラインポリシーの違いと、Terraformの基本的な記法を理解していることを想定しています。
:::

## クォータについて

クォータとは、「各AWSサービスで作成・使用できるリソースの上限値」のことです。
特に明記がない限り、クォータはリージョン固有です。

https://docs.aws.amazon.com/ja_jp/general/latest/gr/aws_service_limits.html

https://docs.aws.amazon.com/ja_jp/IAM/latest/UserGuide/reference_iam-quotas.html

## 検証内容
### アカウントのクォータを確認する

下記のコマンドをターミナルで入力してレスポンスを確認します。
```
aws iam get-account-summary
```

レスポンスからクォータ部分を一部抜粋して見ると、**AttachedPoliciesPerRoleQuotaが20になっている**ことを確認できました。
```json
{
    "SummaryMap": {
        "GroupPolicySizeQuota": 5120,
        "AttachedPoliciesPerUserQuota": 10,
        "PoliciesQuota": 1500,
        "AssumeRolePolicySizeQuota": 2048,
        "PolicyVersionsInUseQuota": 10000,
        "VersionsPerPolicyQuota": 5,
        "AttachedPoliciesPerGroupQuota": 10,
        "PolicySizeQuota": 6144,
        "UserPolicySizeQuota": 2048,
        "RolePolicySizeQuota": 10240,
        "AttachedPoliciesPerRoleQuota": 20
    }
}
```

#### 【参考】aws iam get-account-summaryで取得できるクォータ
| SummaryMapのキー | 説明 | 値 |
|---|---|---|
| `GroupPolicySizeQuota` | グループのインラインポリシー合計 | 5,120文字 |
| `AttachedPoliciesPerUserQuota` | ユーザーあたりの管理ポリシー | 10 |
| `PoliciesQuota` | カスタマー管理ポリシー数 | 1,500 |
| `AssumeRolePolicySizeQuota` | ロールの信頼ポリシーの長さ | 2,048文字 |
| `PolicyVersionsInUseQuota` | アカウント全体のポリシーバージョン総数 | 10,000 |
| `VersionsPerPolicyQuota` | ポリシーあたりのバージョン数 | 5 |
| `AttachedPoliciesPerGroupQuota` | グループあたりの管理ポリシー | 10 |
| `PolicySizeQuota` | 管理ポリシーのサイズ | 6,144文字 |
| `UserPolicySizeQuota` | ユーザーのインラインポリシー合計 | 2,048文字 |
| `RolePolicySizeQuota` | ロールのインラインポリシー合計 | 10,240文字 |
| `AttachedPoliciesPerRoleQuota` | ロールあたりの管理ポリシー | 20 |

なお、ユーザーの`AttachedPoliciesPerUserQuota`とグループの`AttachedPoliciesPerGroupQuota`は10のままです。
今回引き上げられたのはロールのクォータのみになります。

### ポリシーを20個アタッチしたロールを作成してみる

テスト用のIAMロールを作成し、管理ポリシーを20個アタッチしてみます。

使用したファイルは下記です。検証用なので、Claude Codeに適当に作成してもらいました。なお、provider.tfやbackend.tfは割愛します。

<details><summary>main.tf</summary>

```hcl
data "aws_caller_identity" "current" {}

data "aws_iam_policy_document" "assume" {
  statement {
    effect  = "Allow"
    actions = ["sts:AssumeRole"]

    principals {
      type        = "AWS"
      identifiers = [data.aws_caller_identity.current.account_id]
    }
  }
}

resource "aws_iam_role" "test" {
  name = var.name_prefix
  description        = "Temporary role to test the PoliciesPerRole quota. Safe to delete."
  assume_role_policy = data.aws_iam_policy_document.assume.json
}


locals {
  managed_policy_arns = [
    "arn:aws:iam::aws:policy/AmazonEC2ReadOnlyAccess",
    "arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess",
    "arn:aws:iam::aws:policy/AmazonDynamoDBReadOnlyAccess",
    "arn:aws:iam::aws:policy/AmazonRDSReadOnlyAccess",
    "arn:aws:iam::aws:policy/AWSLambda_ReadOnlyAccess",
    "arn:aws:iam::aws:policy/CloudWatchReadOnlyAccess",
    "arn:aws:iam::aws:policy/CloudWatchLogsReadOnlyAccess",
    "arn:aws:iam::aws:policy/IAMReadOnlyAccess",
    "arn:aws:iam::aws:policy/AWSCloudTrail_ReadOnlyAccess",
    "arn:aws:iam::aws:policy/AmazonSNSReadOnlyAccess",
    "arn:aws:iam::aws:policy/AmazonSQSReadOnlyAccess",
    "arn:aws:iam::aws:policy/AmazonVPCReadOnlyAccess",
    "arn:aws:iam::aws:policy/AmazonRoute53ReadOnlyAccess",
    "arn:aws:iam::aws:policy/AWSCloudFormationReadOnlyAccess",
    "arn:aws:iam::aws:policy/AmazonSSMReadOnlyAccess",
    "arn:aws:iam::aws:policy/AmazonEC2ContainerRegistryReadOnly",
    "arn:aws:iam::aws:policy/AWSXrayReadOnlyAccess",
    "arn:aws:iam::aws:policy/AmazonElastiCacheReadOnlyAccess",
    "arn:aws:iam::aws:policy/AmazonRedshiftReadOnlyAccess",
    "arn:aws:iam::aws:policy/AmazonKinesisReadOnlyAccess",

    # クォータ超過テスト用。この行のコメントを外すと 21 個目になる。
    # "arn:aws:iam::aws:policy/AWSSupportAccess",
  ]
}

data "aws_iam_policy" "attached" {
  for_each = toset(local.managed_policy_arns)

  arn = each.value
}

resource "aws_iam_role_policy_attachment" "test" {
  for_each = toset(local.managed_policy_arns)

  role       = aws_iam_role.test.name
  policy_arn = data.aws_iam_policy.attached[each.key].arn
}

```
</details>

<details><summary>variables.tf</summary>

```hcl
variable "region" {
  type        = string
  description = "リソースを作成するリージョン"
  default     = "ap-northeast-1"
}

variable "name_prefix" {
  type        = string
  description = <<-EOT
    この構成が作るロールの名前。
    検証用リソースだと一目で分かる名前にしておき、破棄漏れに気付けるようにする。
  EOT
  default     = "sandbox-quota-test"
}
```
</details>

<details><summary>terraform.tfvars</summary>

```hcl
region = "ap-northeast-1"
```
</details>


上記のファイルを配置したディレクトリに移動し、ローカルからinit→plan→applyします。

```
terraform init
```

![terraform init が成功し、S3バックエンドが設定されたことを示すターミナル出力](https://raw.githubusercontent.com/hot377/tech-blog/main/images/2026-08-30/terraform-init.png)

initが通ったのでplanを実行します。
作成されるリソースが21個であることが分かります。
ロール1個とポリシーのアタッチメント20個で、合計21個です。
```
terraform plan
```

![terraform plan の結果。Plan: 21 to add となり attached_policy_countが20になっている](https://raw.githubusercontent.com/hot377/tech-blog/main/images/2026-08-30/terraform-plan-policy-20.png)

次に、applyを実行します。

```
terraform apply
```

applyが通ったので、マネジメントコンソールを見てみると、
ポリシーが20個アタッチされたロールが作成されたことを確認できました。

![terraform apply の結果。Apply complete! Resources: 21 added と表示されている](https://raw.githubusercontent.com/hot377/tech-blog/main/images/2026-08-30/terraform-apply.png)

![マネジメントコンソールのIAMロール画面。許可ポリシーが20個アタッチされている](https://raw.githubusercontent.com/hot377/tech-blog/main/images/2026-08-30/managed-console.png)

### ロールに21個目のポリシーをアタッチしようとするとどうなるか？

main.tfのコメントアウト部分を外して、再度applyしてみます。

![再度applyしたときの出力。21個目のAWSSupportAccessが追加対象となり、attached_policy_countが20から21に変化する](https://raw.githubusercontent.com/hot377/tech-blog/main/images/2026-08-30/terraform-apply-policy-21.png)

エラーになりましたね。
クォータを超過すると下記のエラーが出るようです。
StatusCodeも409なんですね。
```
LimitExceeded: Cannot exceed quota for PoliciesPerRole: 20
```

![apply が失敗し、LimitExceeded: Cannot exceed quota for PoliciesPerRole: 20 というエラーが表示されている](https://raw.githubusercontent.com/hot377/tech-blog/main/images/2026-08-30/terraform-apply-policy-21-error.png)


### 後片付け
対象のディレクトリで削除対象を確認し、削除します。
```
terraform plan -destroy
```

削除対象を確認し、OKだったら以下を実行します。

```
terraform destroy
```

最後にマネジメントコンソールでも削除されることを確認します。

## まとめ
- 1ロールあたりの管理ポリシーのデフォルトクォータは20個になっていた。
- 21個目をアタッチしようとすると、エラーになった。
- エラーメッセージは、「LimitExceeded: Cannot exceed quota for PoliciesPerRole: 20」となる。
